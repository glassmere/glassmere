# Feature coverage

Status of the 62 goals in [the original feature list](feature-list.md) as of 2026-09-22, after milestone 27. "Done" means the contract exists, is tested and is documented in a milestone report; "Partial" names what exists and what is missing; "Planned" points at the roadmap phase.

| # | Goal | Status | Notes |
| ---: | --- | --- | --- |
| 1 | Immediate-mode ergonomics, retained internals | Done | `ui.button(...)` over a retained tree with persistent focus, scroll, editing, caches and animation state. |
| 2 | Stable widget identity | Done | Explicit/positional keys, monotonic `NodeId` shared by layout, input, focus, accessibility, testing and the inspector. |
| 3 | Incremental updates | Done | Property comparison limits layout and paint work, and `Ui::memo` keeps a subtree without declaring it again while the state it was declared from is unchanged, without missing the input inside it (milestone 15). |
| 4 | Incremental layout | Done | Taffy dirty subtrees; same-size text changes skip layout. |
| 5 | Incremental rendering | Done | Damage tracking, subtree paint caches, retained GPU buffers and text batching, and presentation that redraws only the damaged pixels on both renderers, proved frame by frame against a full repaint (milestone 15). |
| 6 | First-class virtualization | Done | Lists, trees and grids realize only the viewport (milestone 4) and the code editor only the visible lines (milestone 7b). Measured: a million-row table declares 373 elements a frame, a hundred-thousand-node tree 139, and a 3.2 MB file opens in 47 microseconds (milestone 24). |
| 7 | Excellent text system | Done | Unicode, graphemes, fallback, ligatures, emoji, IME, selection, clipboard, undo/redo, rich text blocks with links, syntect highlighting, a rope document with virtualized line rendering, a WYSIWYG rich text editor with Markdown persistence. Visual or logical caret order in bidirectional text with caret affinity, right-to-left alignment. A paragraph can be forced to start in either direction, and the find bar searches by regular expression behind the `regex` feature (milestone 19). Missing: vertical writing modes, hyphenation. |
| 8 | Accessibility from day one | Done | AccessKit roles, labels, actions, keyboard navigation, tree visible in the inspector's Accessibility tab. Screen-reader speech review remains manual. |
| 9 | Powerful focus system | Done | Keyboard focus, pointer capture, Tab traversal, focus scopes with trap/restore/memory, modal focus in dialogs, geometric arrow navigation, predictable restoration (milestone 6c). |
| 10 | Modern layout engine | Done | Flexbox, grid with tracks/areas/repeat/minmax, intrinsic sizing, percentages, min/max, aspect ratio, alignment including text-bottom baseline, absolute popups (milestone 6b). Baseline alignment uses the font's own ascent, `Ui::responsive` gives a container's width to its content, and `Style::offset` places children by hand inside it (milestone 19). Missing: a custom layout trait, and flex wrapping. |
| 11 | Typed styling system | Done | Typed `Style` with builders, Rust classes, stylesheet classes with `extends`, tokens, hover/pressed/focused/disabled overrides, text inheritance and hot reload from disk (milestone 6a), background images with fit modes and nine-slice from code or sheets (milestone 8b). Compile-time validation applies to the Rust API only. |
| 12 | Excellent theming | Done | Dark and light token themes, runtime switching, OS preference via winit, stylesheet token overlays and user sheets (milestone 6a). |
| 13 | Animations in the property system | Done | `Style::transition`, `enter`/`exit` effects, `layout_transition`, keyframe `Animation`, easing curves, reduced motion; composited as GPU layers. Missing: spring physics, per-property timing, OS reduced-motion detection. |
| 14 | Renderer-independent UI core | Done | Core emits a `Scene` display list; no wgpu types in core. |
| 15 | Multiple rendering backends | Done | wgpu (Direct3D 12, Vulkan, Metal, OpenGL) and `CpuRenderer`, which rasterizes the same display list without an adapter and agrees with the GPU within a measured tolerance (milestone 14b). The desktop host paints with it when no adapter works, and on request, through softbuffer (milestone 14c). |
| 16 | Efficient GPU architecture | Done | Instanced quads, glyph atlas, a shared image atlas with vector images rasterized per size (milestone 8a), offscreen layers, batching, rectangular clipping. Damage-limited redraw into a persistent canvas (milestone 15), linear and radial gradients and analytic rounded-box shadows on both renderers (milestone 18). Missing: paths, mipmaps, conic gradients. |
| 17 | Custom rendering escape hatch | Done | `CustomWidget` leaves paint primitives, and `Primitive::Custom` with `Renderer::set_custom_draw`, registered through `AppOptions::gpu`, hands a rectangle to the application's own wgpu code with the pass, the scissor and the scale (milestone 18). Missing: a software equivalent for the CPU renderer. |
| 18 | Rich widget library | Done | Button, checkbox, radio, slider, text input, combo, menu, context menu, tooltip, popover, tabs, split panes, tree, virtual list, data grid, modal and non-modal dialogs, docking, rich text, code editor, rich text editor, images, number input and autocomplete (milestone 9a), toasts (milestone 9b) and a property grid with a derive macro (milestones 9c and 9d). |
| 19 | Professional-grade DataGrid | Done | Virtual rows, sorting, selection, huge datasets; column resizing, reordering and hiding in app-owned state, by drag and from a keyboard menu (milestone 10b); a cell cursor and typed in-place editing with model validation (milestone 10c); a filter row whose texts the model applies (milestone 10d); sideways scrolling with frozen and virtual columns (milestone 10e). Missing: pinned data rows, range selection with copy and paste. |
| 20 | Docking/layout system | Done | `DockLayout` with splits, tab groups, in-window floating groups and detached OS windows; drag onto drop indicators plus a keyboard panel menu; text format and `serde` feature. Missing: cross-window tab drags, persisted detached-window geometry, scrolling tab strips. |
| 21 | Powerful event system | Done | Pointer (left and right buttons), touch contacts, keyboard, drag/drop, capture per pointer, context-menu requests, timed wakes, pan, pinch and rotation gestures (milestone 13); `Ui::event_area` watches the events of a subtree on the way down or up, may consume them, and carries custom events from `Ui::emit` (milestone 17). |
| 22 | Input abstraction independent of the OS | Done | Core consumes `Event`; winit lives only in the host crate. |
| 23 | Mouse/touch/stylus support | Done | Mouse; touch and pen contacts as independent pointers with tap, pan, kinetic scrolling, long press and pressure (milestones 13b and 13c); `Ui::gesture_area` with pan, pinch and rotation (milestone 13d); double tap, swipe, and word selection by resting or tapping twice in text, with the drag extending it (milestone 17). `Pen` carries tilt and buttons; no desktop backend reports them, since winit gives pressure alone. |
| 24 | First-class keyboard shortcuts | Done | Commands with platform-primary shortcuts, scopes that follow the focus, user bindings through `Context::set_binding`, and `Ui::command_palette` (milestone 16). |
| 25 | Command architecture | Done | `Command` carries an id, a label, a binding, enabled state and a scope, shared by its button, its shortcut, `MenuItem::command` and the palette (milestone 16). |
| 26 | Clipboard and drag-and-drop | Done | Text, images and the application's own private formats on the clipboard, in-process text, item and file drags that cross to the application's other windows, incoming OS file drops, and outgoing OS file drags on Windows and macOS with the outcome reported to the source (milestones 13a, 25). Only files leave for another application, and not from Linux. |
| 27 | Multi-window support | Done | Independent windows on one device, native modal dialog windows that block their owner, shared state via `Arc` and mailboxes, DPI scaling per screen, and `AppOptions::placement` for which screen a window opens on (milestone 20). Tried on one screen only. |
| 28 | Strong async integration | Done | Bounded mailbox and wake handle, and `Tasks` for jobs that can be cancelled, superseded by key, and stream many results, with a superseded job's results dropped before the view sees them (milestone 21). No executor is forced: a job is a thread or a future on the runtime the application already has. |
| 29 | Optional reactive state | Done | Ordinary Rust state stays the default, and `Store` adds signals and memos that record what they read, mark what depends on them and recompute at the next read (milestone 22). |
| 30 | Ordinary Rust state | Done | Views borrow `&mut` application state. |
| 31 | Observable dependency graph | Done | Per-node "last declaration changed" flags and repainted nodes, and a State tab listing a store's values, their versions, whether they are out of date and what each one read, with the newest change picked out (milestone 22). |
| 32 | Built-in native DevTools | Done | F12 inspector: tree, box model, computed style, focus/hover state, accessibility view, event log, repaint/damage overlays, frame timings, a GPU tab with pass times, draw counters, renderer memory by category and the driver's report (milestone 12), a Scene tab with the layers of the last frame and what the window holds on the CPU (milestone 24), and a State tab for a reactive store (milestone 22). |
| 33 | Performance profiler | Done | Declare/layout/paint/render CPU timings, dirty flags, created/reused/removed counts, paint cache hits, CSV export, `tracing` spans; GPU time per frame and pass through timestamp queries, draw calls, quads, passes and GPU memory, measured only while an inspector is open (milestone 12), text shaping timed on its own and the declaration's own allocation counted exactly (milestone 24). The glyph atlas is not in the memory total: glyphon does not report its size. |
| 34 | Hot reload | Done | Stylesheets and themes reload in place; any file through `Ui::watched_bytes`/`watched_text`; Rust code through `rust-gui-dev`, which rebuilds and restarts with app state (`Ui::hot_state`) and window geometry kept (milestone 7g). Image files reload in place too (milestone 8a). Missing: in-process code swapping. |
| 35 | Headless UI testing | Done | `rust-gui-testing` harness with real input paths and application state access. |
| 36 | Snapshot testing | Done | Text snapshots for tree, layout, accessibility and scene; opt-in pixel snapshots with a bundled font. |
| 37 | Semantic testing API | Done | `by_label("Save")` then `click`; key paths for disambiguation. |
| 38 | Deterministic rendering/testing | Done | Synthetic measurer for logic tests; bundled Fira Mono for pixel references. Cross-driver tolerance still to be confirmed in CI. |
| 39 | Localization | Done | Right-to-left windows and subtrees with mirrored layout and widgets, direction detected from the OS locale (milestone 7f). Fluent message catalogs with plurals, a fallback chain and run-time language switching; the framework's own strings translatable, with Czech and German shipped (milestones 11a and 11b); a compile-time checked `tr!` and CLDR numbers, dates and times through the opt-in `icu` feature, followed by the number widgets (milestones 11c and 11d). Missing: relative times, lists, currencies, other calendars. |
| 40 | High-DPI support | Done | Per-window scale factor, fractional scaling, DPI-aware accessibility bounds. |
| 41 | Platform integration | Done | Accessibility APIs, IME, clipboard, window titles and decorations, and the desktop's light and dark preference. Behind the `platform` feature: file dialogs, notifications, the application menu, a tray icon, and the files an association opens (milestone 26). A window menu bar is the framework's own on Windows and Linux, where the platform's needs unsafe calls. |
| 42 | Native-first desktop focus | Done | Windows verified by hand and by script. Windows, Linux and macOS run formatting, the whole suite with every feature, clippy and a windowed smoke run on every push, Linux under Xvfb with the CPU renderer (milestone 27). Interactive checks are Windows only. |
| 43 | Clean platform abstraction | Done | Host crate isolates winit/wgpu/AccessKit. |
| 44 | Low allocation architecture | Done | Retained nodes, reused GPU buffers, paint chunks and element vectors, and no widget trait objects anywhere. What a declaration allocates is bounded by what is visible and measured per frame: 373 elements and 2.5 kB for a table of a million rows (milestone 24). |
| 45 | Predictable ownership | Done | Views are plain closures over `&mut` state; no `Rc<RefCell>` in application code. |
| 46 | Good escape hatches | Done | A widget of your own with `Ui::widget`, drawing of your own with `Primitive::Custom` and `AppOptions::gpu`, layout of your own with `Style::offset` inside `Ui::responsive`, input of your own with `Ui::event_area`, and pixels without a window through `CpuRenderer` (milestones 18, 19, 23). |
| 47 | Modular crates | Done | core, scene, render-wgpu, winit, testing, devtools, facade. Layout/text/style/widgets live inside core and scene for now. |
| 48 | No forced proprietary DSL | Done | Plain Rust. |
| 49 | Compile-time checked UI APIs | Done | Typed styles, lengths and models; `tr!` checks a message key and its arguments, `style_sheet!` parses a stylesheet, and `#[derive(Properties)]` checks a field's editor, all while the crate compiles (milestones 11c, 27). What cannot be checked there panics at declaration with a message, listed in [the stability note](api-stability.md). |
| 50 | Excellent documentation | Partial | Architecture and milestone reports. Missing: widget-building, custom renderer, state, accessibility and performance guides. |
| 51 | Stable public API | Done | [A written policy](api-stability.md) with tiers, versioning and deprecation, and a snapshot of every public item and method of the ten crates an application depends on, guarded by a test so that a change is deliberate (milestone 27). The version is 0.1: the promise is that changes are written down, not that there will be none. |
| 52 | Strong benchmarks | Done | The `bench` example runs the four cases the list names: a million-row table, a hundred-thousand-node tree, a 3.2 MB text file and four hundred animating elements, with the 10,000-node declaration benchmark, the one-million-row list test and the 6,000-frame stress beside them (milestone 24). |
| 53 | Low idle CPU/GPU usage | Done | Event-driven loop sleeps between events; no continuous redraw. |
| 54 | Fast startup | Done | Measured with `RUST_GUI_STARTUP`, which prints each step: 491 ms to the first frame, of which 56 ms is the framework and 278 ms is the driver enumerating adapters. A window painted by the CPU renderer is up in 56 ms (milestone 24). |
| 55 | Small deployment footprint | Done | A whole application is 15.8 MB with every default feature and 12.3 MB with none, with nothing to install beside it (milestone 24). |
| 56 | Excellent error diagnostics | Done | Duplicate keys, duplicate shortcuts, invalid models and clip imbalance panic with messages; stylesheet, dock layout and watched-file errors carry line numbers or paths, unknown classes surface in the inspector, and controls without an accessible name are reported (milestone 7h). Files that fail to load and font families that are not installed are reported too (milestone 25). |
| 57 | Framework-level diagnostics | Done | Unstable ids, needless relayout, excessive repainting, controls without an accessible name, oversized layers and huge unvirtualized containers, through `Context::diagnostics`, the inspector and `tracing` (milestone 7h). |
| 58 | Small core with extension points | Done | Models, custom leaves and `Ui::widget`, proved by a control built outside the framework with nothing private to it (milestone 23). |
| 59 | Component ecosystem | Done | A reusable widget is a normal crate depending on the facade: `examples/dial-widget` is one, with its own library, example and tests (milestone 23). Version coupling is the facade alone, though the API is not yet stable (row 51). |
| 60 | Excellent custom-widget API | Done | Size, paint, semantics with a value, the pointer, the keyboard and the wheel in the widget's own coordinates, hover, press, focus and enablement, theme and stylesheet access, and the same test harness the built-in controls use (milestone 23). |
| 61 | Clear performance model | Done | [The performance guide](performance.md): what makes each phase run, what a frame costs in the four hardest cases, what startup and the binary weigh, and which inspector tab answers which question (milestone 24). |
| 62 | Central promise | Partial | Retained incremental engine behind an immediate-style API is in place; capability, styling and tooling breadth continue in phases 6 and later. |
